# 验收清单（写完必做：五查，由独立验收 agent 执行）

> **主写副验（硬规则）**：写正文的 agent **不得自验**。必须起一个全新的独立验收 agent（信息隔离），只喂它「产物 + 本清单 + 模板路径 + 范文原文路径」。写作 agent 的"我读过了"自述不可信，不作为依据。
>
> **核心原则**：验收是「外部核对」，不是「内在反思」。副验 agent 不采信写作 agent 的自我陈述，而是自己拿范文原文 + 模板去核对产物——**引用对得上原文才算数**。AI 生成不可信，任何"看起来对"就宣布通过都是假验收。
>
> **范文库（可插拔，允许为空）**：范文库目录为 `references/范文原文/`，放入任意篇数 `.md` 即生效。库内非空 → **完整模式**，按本清单核对原文引用；库内为空 → **降级模式**，查1/查2 按各自标注的降级口径执行，查3/查4/查5 强度不变。降级只削弱"引用原文核对"这一项，不影响验收整体有效性；验收反馈须注明运行模式。

## 查 1 · 过程痕迹（有没有真读范文 + 模板）

不查"日志文件"（那是写作 agent 的自述，可伪造），查一件客观事实：**追溯表里的「范文引用」能不能和范文原文逐字对上**。

- 能对上 = 真读过范文原文；
- 对不上 / 引用在范文原文里找不到 = 没读或编造，打回。

**核对方式（完整模式）**：副验 agent 自己 Read 范文库里对应的 `.md` 文件（文件名不固定，以范文库实际内容为准），把追溯表里每条「范文引用」去掉空白后，与范文原文做子串比对。命中 = 真；不命中 = 打回。

**降级口径（范文库为空时）**：不再核对引用原文，改为核对两项——① 追溯表是否逐位置落到 `paper_skeleton.md` 的具体位置（位置名要对得上）；② 该位置是否只用了要素清单内的要素。两项都过即算查1 通过，反馈中标明「无范文降级模式」；追溯表的第三列由「参考范文哪一段」改为「参考骨架哪个位置」。

## 查 2 · 逐句追溯（每一句怎么来的）

写出的每个位置，逐句核「对应哪个要素 + 参考了范文哪一段」：

| 检查项 | 标准 | 不过的后果 |
|--------|------|-----------|
| 每句有主 | 每一句都能对应上模板该位置的一个功能要素 | 对应不上的句子 = 加戏，删 |
| 要素在清单内 | 每句对应的要素，在该位置的要素清单里 | 不在 = 加戏，删 |
| 引用真实（仅完整模式） | 每条「范文引用」能在范文原文里定位到 | 定位不到 = 编造，打回；**范文库为空时本项跳过**（走降级口径） |

**必产物 · 逐句追溯表（硬性，缺了 = 任务没完成，不准交付）**：

| 段落（位置） | 每句对应哪个要素 | 参考范文哪一段（可定位到原文） |
|-------------|-----------------|------------------------------|
| 3.3 求解段 | 算法 + 参数依据 | B046「求解无约束的方法各种各样……」段落，松散罗列风格 |
| 4.1 方法选择段 | 对比 → 选择 → 理由 | B046「求解无约束的方法各种各样……本文选择了……鲸鱼算法」段落 |

说明：引用记的是「参考了范文哪一段的什么风格」，不是「逐字照抄哪句」。写法仍然自由，句子是 AI 自己的；表的作用是证明「真的读了范文、学到了味道」，而不是逼着抄。**没交这张表 = 位置没写完，交付即不合格。**

## 查 3 · 效果达成（达到什么效果）

| 检查项 | 标准 |
|--------|------|
| 要素齐全 | 该位置要求的功能要素都写到了（方法选择段 = 对比 + 选择 + 理由，缺一不可） |
| 逻辑走对 | 要素之间的逻辑（递进 / 因果 / 对比 / 并列）走对 |
| 数值真实 | 结果句的数值能反查代码 / 数据 |

数值反查（建议手段，非强制）：用 `scripts/audit_numbers.py` 把论文每个数值和代码输出（results CSV）比对，对不上打回。

## 查 4 · 内容门禁（有没有 AI 味 / 空洞 / 重复）

| 检查项 | 标准 |
|--------|------|
| AI 高频词 | 扫「不仅…而且、毋庸置疑、综上所述、值得注意的是、标志着、充分体现」等，命中过多 = 打回 |
| 空洞结论 | 一句「模型稳健」带过、无数值无分析 = 打回 |
| 重复段落 | 同一件事在结果分析和模型检验讲两遍 = 删一处 |
| 死板句式 | 「首先/其次」「一方面/另一方面」堆砌 = 打回 |

## 查 5 · 交付文件结构体检（防格式转换残留）

| 检查项 | 怎么查 | 有问题 = |
|--------|--------|---------|
| 分节符 | 解包 docx 数段落内 sectPr，应 0 | 多余分节符 → 大块空白、页码重复，返修 |
| 公式形式 | 数 oMath（原生）vs drawing（图片） | 全图片无原生 = 转换残留，易乱码，返修 |
| 乱码字符 | 扫 ⑴(ω) į(斜体 i) ∨(∀) 等 | 有 = 编码错乱，返修 |
| 空格残留 | 扫「中文+空格+中文」 | 有 = 术语替换残留，返修（代码字符串里的不算） |
| 附录源码 | 附录完整源代码在不在 | 缺 = 可能取消评奖资格，返修 |
| **AI 声明** | 正文有没有 AI 工具使用声明、**位置是否在参考文献之前** | 缺失或位置错 = 格式违规，返修；用 AI 还须在支撑材料附《AI 工具使用详情.pdf》 |
| **匿名** | 摘要页 / 正文 / 附录 / 支撑材料内是否出现姓名、学校、赛区、队号、学号（含 PDF 属性、图片 EXIF、代码注释） | 出现 = 可能取消评奖资格，返修 |
| **承诺书 / 编号页** | 电子版论文与支撑材料里是否误放了承诺书、编号专用页 | 放了 = 返修（电子版首页必须是摘要页） |
| **提交体积** | 论文文件 ≤20MB、支撑材料包 ≤20MB，且论文未压缩提交 | 超限 = 提交无效，返修 |
| **摘要页长** | 摘要页（标题+摘要+关键词）是否控制在一页内 | 超一页 = 官方"原则上不超过一页"不符，返修 |

（建议手段，非强制：docx 用 `scripts/audit_docx.py` 扫分节符/乱码/空格，PDF 用 `scripts/pdf_check.py` 查页数/图片。脚本是建议，检查项本身才是硬性的。）

**原因（知识，供判断）**：这类残留最常见来自「在线文档编辑器导出 Word」——导出时 ① 公式渲染成图 ② 在每个公式/表格/章节间插「下一页分节符」 ③ 字符映射错（ω→⑴、斜体 i→į、∀→∨） ④ 术语替换残留空格。直接编译 PDF（Typst）无此问题。

**修复建议（不强制，按项目实际定）**：优先用规范工具链直接产出目标格式；拿到转换来的 docx 先体检、清理分节符/乱码/空格再交付。用什么工具、怎么生成，本 skill 不锁死。

## 最后 · 人工复核

「语义合理性、严谨性」这类判断，AI 验不了，交付前由人过一遍。

## 验收结论（简短反馈，必产物）

验收 agent 必须写**简短反馈**，格式：

> 查1 过程痕迹：引用对原文 ✓ / 有编造 ✗
> 查2 逐句追溯：N 句对应 要素1/要素2/要素3 ✓
> 查3 效果达成：要素齐全 ✓ 数值反查 ✓
> 查4 内容门禁：无 AI 套话 ✓
> 查5 结构体检：分节符 0 / 乱码 0 / AI 声明在参考文献之前 ✓ / 匿名 ✓ / 无承诺书编号页 ✓
> 结论：通过 / 不通过（不通过写明哪查、哪项、为什么）

五查都过才准交付。任一不过，写明「哪查、哪项、为什么」，打回重写，再验。**没有这份反馈 = 任务没完成。**
